## 3. コンセプトの定義〔2分〕

**コンセプト＝機能を形態に対応づけるアイデア。**  
説明の型：**何に、どんな変化を、何によって起こすか。**

| 言い方 | 何を述べているか |
| --- | --- |
| 「燃費が良い」 | 目標・属性 |
| 「減速時のエネルギーを回収する」 | 機能 |
| 「モーター・電池」 | 形態・手段 |
| 「モーターを発電動作させ、回収した電力を電池へ蓄える」 | 機能と形態を結ぶコンセプト断片 |

## 4. 創造性をどう使うか〔3分〕

- 新規性を持つ出力に向け、意図的に努力する。
- 発想段階と、影響・有効性を評価する段階を分ける。
- 自由な連想と、構造化した発想の両方を使う。

| 非構造化 | 構造化 |
| --- | --- |
| ブレインストーミング、自由連想、ひらめき | 分解と再結合、候補の一覧化、形態マトリクス、TRIZなど |

**問いの置き換えの例：** コルクを抜く → ワインにアクセスする。

<a id="steps-p282"></a>

[![手順2後半・3・4：断片の生成、統合、選別（原資料から切り出し）](assets/chapter12/steps-p282.png)](assets/chapter12/steps-p282.png)

**手順2後半・3・4｜断片の生成、統合、選別。** 出典：[原著p.282](../ref/IMG_0047.png)。

出発点は、SPS（システム問題記述）と目標である。以下の例は、本章のハイブリッド車の説明を4ステップに沿ってつないだもの。発表の2分間では各項目の冒頭と出力を中心に説明し、具体例は続く6〜9節で詳しく扱う。

### 5.1 Develop：価値を実現する全体コンセプトを複数つくる

**「何を達成したいか」から、「何によって、どう実現するか」へ具体化する。** 問題記述と目標を読み直し、価値に関わる対象と、その対象に必要な変化を捉える。そのうえで、作用と実現手段を結びつけた全体案を考える。各案が元の問題と目標に合うかを確かめ、必要なら問題の置き方も見直す。

例：人と荷物を安価で環境に配慮して運ぶという価値から、ガソリン／電気のハイブリッド車を用いて移動する構想へ具体化する。本章の事例は前章までの検討を引き継いでこの全体案から始まるが、手順としては複数の全体案を考えてよい。

**次へ渡すもの：** 価値の実現方法を説明できる全体コンセプト候補。詳細な機器構成や接続は、まだ定まっていなくてよい。

### 5.2 Expand：全体案を内部機能へ分解し、各機能の実現方法を増やす

**「この全体案を成立させるには、内部で何が必要か」を掘り下げる。** 全体案が担う複数の機能を展開・分解し、それぞれにDevelopと同じ発想を繰り返す。機能ごとに作用と手段を結びつけた部分案が、コンセプト断片になる。

例：推進を「エネルギーを貯蔵・運搬する」「車両を駆動する」へ分ける。さらに、モーターを発電動作させて減速時のエネルギーを電池へ戻す回生など、内部機能の実現方法を考える。

**次へ渡すもの：** 内部機能ごとのコンセプト断片と、その代替候補。断片は作用と手段の対応であり、独立した部品と1対1に対応するとは限らない。

### 5.3 Evolve and Refine：断片の組合せと相互作用を検討し、統合案へ育てる

**「どの断片を、どうつなげば、全体として成立するか」を検討する。** 候補を体系的に探索し、制約の下で再結合する。接続の整合、機器の共有、機能同士の競合や相乗効果を確かめ、作動原理を説明できる複数の全体案へまとめる。

例：エンジンを発電に使ってモーターで車輪を駆動するシリーズ型と、エンジンとモーターの駆動力を加えるパラレル型を考える。回生とブーストに同じモーターを使う場合は、役割の切替えや電池との関係も検討する。

**次へ渡すもの：** 機能の担い手とエネルギー経路が明確で、相互に比較できる統合コンセプト候補。

### 5.4 Select：目標への適合と、具体化の見通しから少数案を残す

**「求める価値を満たすか」と「良いアーキテクチャへ育つか」の両面で比較する。** 上流で定めた燃費・環境面・価格などの優先目標へ立ち返るとともに、構成の単純さ、機能と形態の対応、開発・製造との整合を見通す。原著は、さらに検討する2〜3案をこの段階の出口として示す。

例：Pughマトリクスで、基準案に対する環境面・燃費の利点と、価格などの不利を明示する。表だけで最終採用案を決めず、優先目標と構成の見通しを合わせて判断する。候補が問題記述や目標を満たすかも再確認し、必要ならそれらを見直す。

**次へ渡すもの：** さらに開発する少数の統合コンセプト。発表では、選別理由と次に確かめる点も説明すると、後の具体化へつながる。

**4ステップのつながり：** 全体案を生み、内部の実現方法を広げ、成立する組合せへ育て、少数案を次へ進める。問題記述や目標の見直しを含む、反復的な活動として捉える。

<details>
<summary>発表者メモ（説明例・参照箇所）</summary>

「最初のDevelopでは、実現したい価値から、それをどう実現するかという全体案を考えます。たとえば、人と荷物を運ぶためにハイブリッド車を使うという構想です。この段階では、内部の駆動構成まで決める必要はありません。

Expandでは、その案を成立させる内部機能を分けます。エネルギーをどう蓄えるか、どう車両を駆動するか。各機能について、作用と手段を結びつけた部分案を増やします。つまり、全体で行った発想を、内部機能に対してもう一度行います。

Evolve and Refineでは、部分案をつなげて全体へ戻します。シリーズとパラレルのように接続を変えれば、同じような機器を含んでいても異なる全体案になります。機器を共有できるか、機能同士が競合しないかも調べます。

最後のSelectでは、燃費や価格などの目標に合うかと、構成・開発・製造がうまくまとまりそうかを両方見ます。さらに検討する2〜3案を残すのが、この段階の出口です。

このように、全体を発想し、内部を発想し、組み上げてから比較するのが4ステップです。途中で問題や目標へ戻ることもあります。次の事例で、その中身を追います。」

参照：12.2の手順、[p.281](../ref/IMG_0046.png)・[p.282](../ref/IMG_0047.png)。全体像は[学習ノート3節](chapter12-notes.md#four-steps)。

</details>

## 6. ハイブリッド車：全体案から分解へ〔3分〕

SPS（System Problem Statement：システム問題記述）を、To–By–Usingで読む。

| SPSの層 | ハイブリッド車の例の要約 |
| --- | --- |
| To | 人と荷物を安価に、環境に配慮して運ぶ |
| By | 燃費と操縦性を備え、顧客自身が運転する |
| Using | ガソリン／電気のハイブリッド車 |

**「ハイブリッド」という名前だけでは、作動原理はまだ決まらない。**

推進を「エネルギーを貯蔵・運搬する機能」と「そのエネルギーで車両を駆動する機能」へ分解する。

<a id="figure12-05"></a>

[![図12.5：一次エネルギー源・キャリア・車両を動かすコンセプト（原資料から切り出し）](assets/chapter12/figure12-05.png)](assets/chapter12/figure12-05.png)

**図12.5｜一次エネルギー源・キャリア・車両を動かすコンセプト。** 出典：[原著p.284](../ref/IMG_0049.png)。

HEV：電動系を備えるハイブリッド車。PHEV：外部充電が可能なハイブリッド車。

<details>
<summary>発表者メモ（説明例・参照箇所）</summary>

「事例は前章までの問題記述を引き継ぎ、すでにガソリン／電気のハイブリッド車という全体案から始まります。両者をどう接続するかはこれから決めます。そこで、エネルギーをどう蓄え、どう車両を動かすかへ分解します。

図12.5は、上から一次エネルギー源、エネルギーキャリア、車両の駆動方式の3層として見ると読みやすくなります。たとえば原油からガソリン、内燃機関という経路と、発電から電力、電池・モーターという経路を区別します。

もうひとつ大事なのが、車内にある機器と、車外から受け入れるエネルギー源の違いです。外部充電をしないHEVは、電池を持っていても外部供給源は燃料ひとつです。PHEVでは燃料と車外の電力の2つになります。」

## 7. 7つの追加機能〔3分〕

| 機能 | 作用と手段の要点 |
| --- | --- |
| 自動停止・再始動 | アイドリングを止め、モーターなどで再始動 |
| 回生ブレーキ | 車両の運動 → モーターの発電 → 電池 |
| ブースト | 電池 → モーター → 加速などの補助 |
| 負荷引上げ | 発電負荷を加え、エンジンの効率的な運転点を利用 |
| 電動走行 | 電池などの電源 → モーター → 車輪 |
| 外部充電 | 車外の電力 → 充電装置 → 電池 |
| 惰行 | 駆動系を切り離して抵抗を減らす |

**断片ごとに機器を増やすとは限らない。** 回生とブーストは、同じモーターや電池を共有できる。

<a id="figure12-06"></a>

[![図12.6：フルハイブリッドによる燃料消費削減の可能性（原資料から切り出し）](assets/chapter12/figure12-06.png)](assets/chapter12/figure12-06.png)

**図12.6｜フルハイブリッドによる燃料消費削減の可能性。** 出典：[原著p.286](../ref/IMG_0051.png)。

**読みどころ：** 自動停止、制御の最適化、回生が燃料消費削減に寄与する。数値は原著の条件付き概算。

<a id="figure12-07"></a>

[![図12.7：モーターと内燃機関のトルク・回転数特性（原資料から切り出し）](assets/chapter12/figure12-07.png)](assets/chapter12/figure12-07.png)

**図12.7｜モーターと内燃機関のトルク・回転数特性。** 出典：[原著p.287](../ref/IMG_0052.png)。

**読みどころ：** 低回転域のモータートルクが発進・加速を補う。縦軸はトルク。

<details>
<summary>発表者メモ（説明例・参照箇所）</summary>

「7つを暗記するより、エネルギーの向きに注目します。回生とブーストは、同じモーターや電池が関わっていても、エネルギーの向きが逆です。外部充電と回生も、どちらも電池を充電しますが、エネルギーの供給元が違います。

負荷引上げは少し直感に反します。エンジンに発電の仕事もさせ、より効率の良い運転点を使い、得た電力を蓄えるという発想です。

回生とブーストを別々の機能として考えても、実際の機器は共有できます。ここで、機能を分けることと、物理部品を分けることの違いが見えます。

同時に、回生で大きな電力が得られても、電池が受け入れられなければ回収できません。統合するときは、こうした依存関係を調べます。」

参照：12.4、[p.285](../ref/IMG_0050.png)・[p.286](../ref/IMG_0051.png)・[p.287](../ref/IMG_0052.png)・[p.288](../ref/IMG_0053.png)。

**図の扱い：** 図12.6は燃料消費削減への寄与、図12.7はブーストの説明に使う。時間が短い場合は図12.7の低回転域に絞って指す。

</details>

## 8. 断片を統合する〔3分〕

| 駆動構成 | 主な経路 |
| --- | --- |
| シリーズ | 燃料 → エンジン → 発電 → モーター → 車輪 |
| パラレル | エンジンの駆動力とモーターの駆動力を合流 |
| 複合 | 両方を組み合わせ、分岐や切替えを行う |

<a id="figure12-08"></a>

[![図12.8：ハイブリッド駆動のエネルギー経路（原資料から切り出し）](assets/chapter12/figure12-08.png)](assets/chapter12/figure12-08.png)

**図12.8｜ハイブリッド駆動のエネルギー経路。** 出典：[原著p.289](../ref/IMG_0054.png)。

統合コンセプト：**ICE／Micro HEV／Mild HEV／Full HEV／PHEV／BEV／FCEV**。

ICEは内燃機関車、BEVは電池からの電力で走る車、FCEVは燃料電池で発電して走る車。7つの特徴は[学習ノート6節](chapter12-notes.md#integrate)を参照。

<a id="figure12-09"></a>

[![図12.9：電動走行距離と電動化度で見るコンセプトの解空間（原資料から切り出し）](assets/chapter12/figure12-09.png)](assets/chapter12/figure12-09.png)

**図12.9｜電動走行距離と電動化度で見るコンセプトの解空間。** 出典：[原著p.289](../ref/IMG_0054.png)。

<details>
<summary>発表者メモ（説明例・参照箇所）</summary>

「同じ部品が含まれていても、つなぎ方と役割が異なります。シリーズは燃料側が電動側へ順にエネルギーを渡し、パラレルは両方の駆動力を加えます。ここが機能と形態の対応を変えるという意味です。

このような駆動経路、エネルギーの貯蔵・運搬、先ほどの内部機能を組み合わせて、本章は7つの代表的な車両コンセプトを整理します。

図12.9では、電動走行距離と電動化度で解空間を見ます。電動化度は、電動機とエンジンの最大合計出力に対する電動機の出力比率です。PHEVという名前が示す外部充電の有無と、シリーズ／パラレルという経路の違いも区別します。

なお、BEVなどは当初のガソリン／電気ハイブリッドという範囲を越えます。こうした案を採用候補とするなら、問題記述のどこを見直すかも明示する必要があります。」

**補足：** 7つの内部機能と7つの車両コンセプトは別。数が同じでも1対1の対応ではない。

参照：12.5、pp.288–291。

## 輪読での議論〔15分〕

以下は本資料で用意した議論の問い。正解を当てるより、各自の経験と本章の枠組みを結びつける。

### 問い1：自分たちは、いつ案を固定しているか〔5分〕

**「直近の設計判断で、実現手段を決める前に比較した全体案は何だったか。比較が難しかった理由は何か。」**

- 最初の1分は各自で具体例を考える。
- 複数案を出せなかった場合は、時間、経験、組織、既存設備、問題の書き方のどこが影響したかを話す。
- 進行役の補助問い：「その前提を固定したままでも、内部機能の実現手段を変えられるか。」

本章との接点：解決手段に依存しない問題記述、候補の保持、認知の偏り。

### 問い2：機能を分解すると、どんな別案が生まれるか〔5分〕

**「共有ドキュメントのレビューで、見落としを減らすシステム」を題材に、実現手段を複数考える。**

**演習の前提：** 優先目標は「確認漏れを減らす」「調整の作業時間を抑える」の2つとする。以下の各行から候補を選び、全体の流れを説明できる案を2つつくる。

| 内部機能 | 候補A | 候補B |
| --- | --- | --- |
| レビュー担当者を決める | 調整担当者が案件ごとに選ぶ | 専門分野などのルールで自動的に割り当てる |
| 確認観点を提示する | 全文書に共通するチェックリストを表示する | 文書の種類に応じてチェックリストを選んで表示する |
| 確認状況を一覧へ反映する | 調整担当者が報告を集めて一覧を更新する | レビュー画面の完了操作を一覧へ自動反映する |

たとえば、全てAを選ぶ案と、「担当者の選定はA、観点の提示と状況の反映はB」を選ぶ案を比べる。列をそのまま選ぶだけでなく、行ごとに組み替えてよい。

進行役の補助問い：「誰が何を操作すると、次の作業が進むか。観点を文書別に変えるなら、文書の種類とチェックリストを誰が管理するか。」

本章との接点：機能と形態の対応、再結合、断片間の競合と相乗効果。

### 問い3：何が分かれば2〜3案を選べるか〔5分〕

**「前の演習の2案を、優先目標とアーキテクチャの両面で比べる。何を調べれば選べるか。」**

- 後ろを見る評価例：確認漏れの発生、調整に要する時間。
- 前を見る評価例：責任分担の分かりやすさ、利用中の文書システムとの接続、変更のしやすさ。
- 進行役の補助問い：「好みで選んでいる箇所と、情報不足で決められない箇所を区別できるか。次に何を試すか。」

最後に、各案について「残す理由」と「判断を変えうる未確認事項」を1つずつ記録する。実際の案件を題材にする場合は、その案件の優先目標へ置き換える。

## 想定質問と答え方

| 質問 | 回答の要点 |
| --- | --- |
| コンセプトとアーキテクチャはどこで分かれるのか | 境界が完全に切れているわけではない。本章は、機能と形態をつなぐアイデアと、実装に向けた構成の言葉を区別する。選別でも一部の具体化が必要で、反復する |
| 発想にも評価を入れた方が効率的ではないか | 初期評価で候補を狭めすぎる問題がある。目標適合のチェックは必要だが、著者は意図的に候補を広げ、その後に比較する活動を重視する |
| 単純な構成なら常に良いのか | 本章は単純さを前を見る評価の例として挙げる。目標を満たすことが前提で、単純さだけの万能な選択規則は示さない |
| Pughマトリクスで一番点が高い案を選べばよいか | 本章の表は総合点を出していない。優先度、評価の根拠、重要な不利、不確実性を確認し、構成の見通しも評価する |
| なぜ1案まで絞らないのか | コンセプトは情報が粗く、まだ判断が変わりうる。比較可能な候補を保ち、より詳しい検討へ進めるため |
| 部分案を全部列挙すれば十分か | 不十分。全体の接続と相互作用を検討し、成立する組合せか、目標に合う統合案かを確かめる必要がある |
| ハイブリッド車の問題なのに、なぜBEVも比べるのか | 本章は車両全体へ解空間を広げている。実務では、当初のUsingを固定制約とするか、別方式も採用候補にするためSPSを見直すかを明示する |
| PHEVはシリーズ型なのか | 外部充電の有無と駆動経路は別。本章でもPHEVにはシリーズ、パラレル、複合を含む |
| 本章の車の評価は今もそのまま使えるか | これは原著当時の説明を理解する資料。現在の製品・市場の比較に使う場合は、別に最新の条件とデータを調べて評価を更新する |
| 著者は結局どの車を選んだのか | この章の比較表には最終採用案が示されていない。選別の方法を説明する事例として扱う |
